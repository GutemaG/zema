## Implementation Walkthrough: local-library-and-player-ui (bolt 1 of 5)

### Summary

Zema now reads the phone's audio files through its own Kotlin MediaStore channel,
stores them in its first Drift database with stable IDs, asks for audio access with an
explanation first, and keeps the library in sync in the background from app start. The
Library tab shows the access states, the first-scan progress, scan errors and a
temporary plain list of tracks.

### Structure Overview

Four layers, each only talking to the next:
- **Kotlin `LibraryChannel`**: reads MediaStore.
- **`LibraryScanner`** (Dart): the only way app code reaches the platform.
- **`LibraryRepository`**: scans, reconciles with `zema_core`, and applies the changes
  through the `LibraryDao` in one transaction.
- **Riverpod providers and controllers**: hold access and sync state for the UI.

Matching and identity rules are pure Dart in `packages/zema_core`, with no Drift or
Flutter types.

### Key Decisions

- **Kotlin channel instead of `on_audio_query`**: the plugin doesn't configure on AGP 9.1 (no `namespace`). The channel is about 200 lines, under our control, and hidden behind `LibraryScanner`.
- **Auto-increment Zema IDs**: re-linking uses the fingerprint, so a UUID adds nothing.
- **Re-link only on a unique fingerprint match**: a wrong re-link would silently move favorites to another song, which is worse than a duplicate entry.
- **Dates stored as UTC text** (`store_date_time_values_as_text`): they read back exactly as scanned, so a rescan of an unchanged library writes nothing. Reading them back with `toUtc()` adds a safety net for rows written in local time.
- **Sync started from the shell, not the Library tab**: the story asks for a background scan at app start, whichever tab opens.
- **Stored tracks hidden while access is off**: matches the story's edge case (access revoked → grant state, not the old list).

### Deviations from Plan

- **Emulator**: used the existing AVD `Medium_Phone_API_37.0` instead of creating `zema_api37`. `avdmanager` needs a system Java this Mac doesn't have.
- **`permission_handler` ^12.0.1, not 13**: 13 needs compile SDK 37; Flutter 3.47 and AGP 9.1 use 36.
- **Albums of untagged files**: MediaStore reports the folder name as the album when there is no album tag, and Zema can't tell that apart from a real album without reading every file's tags. Kept as Android reports it; "Unknown album" only appears when MediaStore gives nothing.
- **Migration test**: Drift only generates migration tests once a second schema version exists. For now there is the v1 schema dump and the generated helpers; the schema-v1 check is written in the test stage.
- **iOS Podfile**: `permission_handler` brings CocoaPods to iOS, so `ios/Podfile` and the two xcconfig includes were added by Flutter.
