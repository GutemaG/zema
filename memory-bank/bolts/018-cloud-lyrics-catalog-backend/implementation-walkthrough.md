## Implementation Walkthrough: cloud-lyrics-catalog-backend (bolt 1 of 4)

### Summary

There is now a local Supabase project in `backend/supabase/`. One migration builds the
catalog schema with Row Level Security on and no policies, so the API exposes nothing
yet. pgTAP tests cover the schema, constraints, cascades and version bumps.

### Files

- **`backend/supabase/config.toml`** (from `npx supabase init`, CLI 2.122)
  - Project ID: `zema`.
  - Turned off: realtime, storage, edge runtime, analytics, the local mail catcher and the SQL seed. The seed is a Dart script in bolt 021.
  - Running locally: Postgres 17, the API, auth and Studio.
- **`backend/supabase/migrations/20261029000000_catalog_schema.sql`**
  - **Types**: eight enums and a `slug` domain (lowercase words joined by hyphens, at most 120 characters).
  - **Tables (9)**: songs, sections, lines, play_order, recordings, sync_timings, reports, user_roles and contributions. The plan said 10 by mistake.
  - **Keys and links**:
    - Lines and play order point to `(song_id, section_id)`.
    - Deleting a song removes its parts; reports and contributions keep their rows, with the song reference set to null.
  - **Timings**: `is_valid_timing` requires starts that are non-empty, non-negative and never going backwards. Equal starts are allowed, for lines sung together.
  - **Versions**:
    - `bump_song_version` runs from row triggers on every child table. Timings reach their song through the recording.
    - `songs_before_update` bumps the version once when the title, transliteration, artist or album changes, and stamps `approved_at` on approval.
    - `songs_before_insert` stamps `approved_at` for a song inserted as approved.
  - **Reports**: `install_hash`, with an index on (install_hash, created_at) ready for the rate limit in bolt 019.
  - **RLS**: enabled on all 9 tables, with no policies.
- **`backend/supabase/tests/database/001_catalog_schema.test.sql`**: 27 pgTAP checks.
- **`backend/README.md`**: requirements, commands, local addresses, rules (keys, migrations only) and a schema table.
- **Git**: `backend/supabase/.gitignore`, generated by the CLI, keeps `.temp`, `.branches` and env files out.

### Checked Against the Running Backend

- `npx supabase start` pulled the images and applied the migration.
- After `npx supabase db reset`, `npx supabase test db` reports all 27 checks passing.
